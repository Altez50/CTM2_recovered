# Спецификация: обновление цен материалов при загрузке накладных

Версия: 0.2
Обновлено: 2026-09-02
Статус реализации: **не начато**; policy, price preview/apply и UI не найдены.
Зависимости: P0/P1 из `DEVELOPMENT_PLAN.md`, `SECURITY_BASELINE_SPEC.md`.
Владелец: требуется назначить. Проверено по коду: 2026-09-02.

---

## 1. Цель

При загрузке строк поступления ТМЦ из Excel поставщика актуализировать цены
в справочнике материалов: накладная — самый частый и достоверный источник
текущей закупочной цены. Сейчас цена из файла попадает только в строки
документа, карточка материала устаревает, и цены в новых сметах/спецификациях
подставляются «из прошлого».

---

## 2. Текущее состояние (AS-IS)

- Импорт строк ТМЦ: `preview_goods_lines_import`
  ([`current/api/goods_services.py`](current/api/goods_services.py)).
  Разбор XLSX/XLS, алиасы заголовков (`ценабезндс`, `цена`, `price` …),
  разрешение материала по `material_id` → `код` → наименование.
- Карточка материала: `materials (code, name, unit_id, price)`
  ([`current/api/database.py`](current/api/database.py)).
- Профили импорта Excel хранятся в `constants` под ключом `goods.import_profiles`
  ([`current/api/import_profiles.py`](current/api/import_profiles.py)).
- `materials.price` при импорте **не изменяется**; цены в диалоге загрузки
  показываются только в строках документа.
- Средняя цена для отчёта остатков считается по регистру инвентаризации
  (`avg_price` в goods_services.py), к карточке отношения не имеет.

## 3. Требования (TO-BE)

### 3.1. Общая логика

При предпросмотре загрузки накладной система сравнивает цену строки
(без НДС) с `materials.price` разрешённого материала и готовит список
изменений. Изменения применяются **только по явному подтверждению
пользователя** (политика по умолчанию — `preview`).

### 3.2. Политика обновления

Новая настройка в `constants` (ключ `goods.price_update_policy`, значение
синхронизируется между узлами):

| Значение | Поведение |
|---|---|
| `off` | Цены не сравниваются и не обновляются (текущее поведение) |
| `preview` *(по умолчанию)* | Различия показываются, пользователь отмечает и применяет |
| `auto` | Все ненулевые различия применяются автоматически при подтверждении импорта строк |

Дополнительно — порог отображения `goods.price_update_threshold_pct`
(по умолчанию `0` — показывать все различия; `5` — только ≥ 5 %).

### 3.3. API

Расширение ответа `POST /api/goods/{kind}/{doc_id}/import-preview`
(и preview без документа, если применимо):

```json
{
  "filename": "nakladnaya.xlsx",
  "detected_columns": { "...": 0 },
  "rows": [ ... ],
  "warnings": [],
  "price_updates": [
    {
      "material_id": 12,
      "material_name": "Цемент М500",
      "unit": "т",
      "current_price": 7800.0,
      "new_price": 8150.0,
      "delta_pct": 4.5,
      "source_line": 3
    }
  ]
}
```

Новый эндпоинт применения (отдельно от применения строк, чтобы обновить
цены можно было даже если строки импортируются позже):

```
POST /api/goods/import-apply-prices
Тело: { "updates": [ {
  "material_id": 12,
  "expected_current_price": 7800.0,
  "new_price": 8150.0,
  "source_line": 3
} ] }
Ответ: { "data": { "updated": 1, "conflicts": [] }, "message": "Обновлено цен: 1" }
Права: manager, admin (как у записи ТМЦ).
```

Применение: `UPDATE materials SET price = ?, modified_at/updated_at = now`;
на каждое изменение — запись в `audit_logs` (кто, что, старое/новое значение).
Обновление условное: если текущая цена уже не равна `expected_current_price`,
материал попадает в `conflicts` и не перезаписывается без нового preview. Повтор
того же apply с тем же idempotency key не создаёт повторный audit/sync event.

### 3.4. Правила сверки цен

1. Сравнивается цена строки **без НДС** (`price_without_vat`) — карточка
   материала хранит цену без НДС (как и в документах).
2. Цена `0` или пустая в файле → различие **не формируется** (нет данных).
3. Материал не разрешён (новый, будет создан) → в `price_updates` не входит;
   цена новой карточки берётся из строки при создании (`auto`-режим
   существующего механизма «Создать материалы»).
4. Один материал встречается в нескольких строках с разными ценами:
   - все различающиеся цены попадают в `price_updates` с пометкой
     `source_line`; применяется **последняя** по порядку строк;
   - если расхождение цен одной позиции > 20 % — `warnings` дополняется
     строкой «Материал X: разные цены в строках 3 и 17 — проверьте файл».
5. Единицы не сравниваются (в файле возможен другой формат записи);
   семантика цены остаётся на ответственности пользователя.
6. Для одного материала в apply остаётся одно итоговое изменение. Если пользователь
   вручную отметил одну из нескольких строк, именно выбранная строка определяет
   `new_price`; правило «последняя строка» применяется только к auto-режиму.

### 3.5. UI

Диалог загрузки из Excel
(`GoodsDocumentFormView.vue` → `GoodsLinesEditor` → диалог импорта):

- Чекбокс «Обновить цены в справочнике материалов» (видим при наличии
  `price_updates`; политика `auto` — включён и залочен).
- Таблица различий: материал, ед., текущая цена, новая, Δ %, строка файла;
  колонка-чекбокс «применить» (по умолчанию все отмечены).
- После применения — toast «Обновлено цен: N» и обновление данных диалога.
- Настройка политики и порога — экран профилей импорта
  (`ImportProfilesView.vue`), секция «Цены» (admin).

### 3.6. Синхронизация

Изменение `materials.price` идёт штатным путём (uuid + `updated_at`):
peer-обмен и разрешение конфликтов «позже изменённая версия выигрывает»
работают без доработок. Apply обязан вызвать штатную регистрацию sync-change;
одного `UPDATE materials` недостаточно. Дополнительных таблиц не вводится.

---

## 4. Не входит в объём (Out of scope)

- Хранение истории цен материала (отдельная фича «карточка цен»).
- Обновление цен в существующих сметах/спецификациях.
- Пересчёт средней цены остатков.

---

## 5. Критерии приёмки

1. Загрузка накладной с изменившимися ценами показывает список различий
   с Δ % и номерами строк файла.
2. Подтверждение обновляет `materials.price`, новая цена подставляется
   в следующий документ по этому материалу.
3. Цена 0/пустая, неразрешённые и новые материалы не порождают различий.
4. Расхождение цен одной позиции > 20 % — предупреждение в `warnings`.
5. Политики `off / preview / auto` соблюдаются, `auto` пишет audit_log.
6. Изменение цены доезжает до офисного узла через sync без ручных действий.
7. Права: применение цен недоступно роли `foreman`.
8. Если цена изменилась после preview, apply возвращает conflict и не затирает
   более новое значение; повтор с тем же idempotency key безопасен.
9. Для дублирующихся строк материала применяется ровно одна выбранная цена,
   audit и sync содержат одно итоговое изменение материала.
