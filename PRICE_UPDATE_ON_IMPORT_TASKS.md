# Задачи: обновление цен материалов при загрузке накладных

Спецификация: [PRICE_UPDATE_ON_IMPORT_SPEC.md](PRICE_UPDATE_ON_IMPORT_SPEC.md)
Статус: не начато; старт после закрытия P0/P1 из `DEVELOPMENT_PLAN.md`.
Оценка — чистая разработка, 1 fullstack-разработчик, без ревью/UAT.

---

## Backend (api)

- [ ] **B1. Хранилище политик** — чтение/запись `goods.price_update_policy`
      (off/preview/auto) и `goods.price_update_threshold_pct` в `constants`
      + хелперы с дефолтами. — **2 ч**
- [ ] **B2. Сверка цен в preview** — расширить `preview_goods_lines_import`:
      для каждой строки с разрешённым `material_id` сравнить
      `price_without_vat` с `materials.price`, собрать `price_updates`
      (current/new, Δ %, source_line), фильтр по порогу, детект
      расхождения цен одной позиции > 20 % → `warnings`. — **4 ч**
- [ ] **B3. Эндпоинт применения** — `POST /api/goods/import-apply-prices`
      (роутер `goods.py`): валидация тела, права manager/admin,
      optimistic check `expected_current_price`, idempotency key,
      `UPDATE materials` + audit actor + регистрация sync-change. — **5 ч**
- [ ] **B4. Тесты (unit/api)** — политики off/preview/auto; цена 0/пустая;
      материал не разрешён / новый; одна позиция с разными ценами;
      права foreman 403; audit/sync; конкурентное изменение после preview;
      повтор idempotency key; выбор одной из нескольких цен. — **6 ч**

## Frontend (web-client)

- [ ] **F1. Таблица различий в диалоге загрузки** — блок «Обновить цены»
      (чекбокс + таблица: материал, ед., текущая, новая, Δ %, строка файла,
      чекбоксы «применить»), вызов apply-prices, toast, обновление данных. — **5 ч**

- [ ] **F3. Настройки в ImportProfilesView** — секция «Цены» (admin):
      политика, порог Δ %. — **2 ч**

## QA / приёмка

## Риски

| # | Риск | Вер. | Влияние | Митигция |
|---|---|---|---|---|
| R1 | Материал разрешается по наименованию → не та карточка → цена обновлена не тому материалу | средняя | среднее | различия показываются пользователю до применения; применяются только отмеченные строки; в таблице видно ед. и наименование |
| R2 | Семантика `materials.price` неоднородна по клиентам (кто-то держал розничную/с НДС) — автообновление «испортит» НСИ | средняя | высокое | политика по умолчанию `preview`; `auto` включает только admin; audit_logs позволяет откатить вручную |
| R3 | Несколько строк одной позиции с разными ценами: правило «последняя строка» неверно при частичных поставках со скидками | средняя | низкое | warning + ручной выбор чекбоксов; по умолчанию не применять спорные |
| R4 | Колонка цены определяется неверно на «экзотических» файлах (цена с НДС в колонке «цена») | низкая | среднее | существующие алиасы заголовков + в предпросмотре видна рассчитанная сумма; при сомнении Δ % аномально большая — глазом видно |
| R5 | Два узла грузят накладную одного поставщика → «пинг-понг» цен при sync | низкая | низкое | LWW-правило оставит последнюю версию; приемлемо, поведение задокументировать |
| R6 | `audit_logs` разрастается при частых автообновлениях | низкая | низкое | писать одну запись на материал (не на строку); ретеншн уже общий |
