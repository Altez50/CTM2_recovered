Версия: 0.2
Обновлено: 2026-09-02
Статус реализации: **частично**. Общий механизм применён к 11 спискам; перенос
табличных частей основания, restore parity, экспорт представления, resize/freeze
и acceptance-тесты не закрыты. Проверено по коду: 2026-09-02

## 1. Цель и область применения

Привести списки форм документов web-клиента к поведению списков динамического
списка тонкого клиента 1С 8.3:

1. Сортировка по заголовку колонки.
2. Фильтрация через поле фильтра (быстрый поиск + быстрый отбор по колонкам).
3. Выбор состава колонок с сохранением (по пользователю).
4. Контекстное меню.
5. Панель команд объектов над списком.
6. Подменю «Ввод на основании» (для документов).

## 2. Текущее состояние (AS-IS)

### 2.1. Что уже реализовано во всех/большинстве списков

| Возможность | Где | Примечание |
|---|---|---|
| Поле быстрого поиска (`search`) | все списки | debounce 300 мс, сброс на стр. 1 |
| Пагинация (page / page_size=20) | все списки | серверная |
| Выбор строк (клик, Ctrl+клик, Shift+клик) | DataTable.vue | выделение + SelectionActionBar |
| Панель действий над выделенным | каждый ListView свой | открыть/провести/удалить/печать |
| Контекстное меню ПКМ | сметы, табель, расход мат. и др. | `useDocumentContextMenu` — только «провести/пометка/восстановить» |
| Двойной клик — открыть | все списки | |
| Заголовок «Создать …» в шапке | все списки | `useHeaderBar` |
| Серверная сортировка `sort_by`/`sort_order` | сметы, дневные отчёты, табели, справочники | `services.py`, `routers/documents.py` |

### 2.2. Чего нет (цель итерации)

- Сортировка кликом по заголовку (колонки не кликабельны, индикатора нет).
- Быстрый отбор по колонкам (строка фильтров под заголовками).
- Настройка состава колонок и её сохранение по пользователю.
- Единая панель команд объектов (сейчас команды разбросаны: шапка + SelectionActionBar + меню).
- Подменю «Ввод на основании».
- Вложенные подменю в контекстном меню (компонент `ContextMenu.vue` умеет только плоский список).
- Сортировка для cost-списков, ТМЦ, платежей (эндпоинты не принимают `sort_by`/`sort_order`).
- Отображение помеченных на удаление строк (зачёркивание), недоступность команд для них.

### 2.3. Существующая инфраструктура для хранения настроек

Таблица `user_settings` уже создана в `database.py:786`:

```
user_settings(user_id, form_name, setting_key, setting_value)
PRIMARY KEY (user_id, form_name, setting_key)
```

Эндпоинтов чтения/записи настроек **нет** (используется только
`read_user_bool_setting` в auth_dependencies.py). См. раздел 4.3.

## 3. Целевое поведение (TO-BE)

Общий принцип: **единая реализация** всех перечисленных механизмов (один компонент
панели команд, один диалог настройки, один composable списка), параметризуемая
декларативной конфигурацией на каждый вид документа. Поведение должно быть
одинаковым во всех 11 списках.

### 3.1. Сортировка по заголовку колонки

1. Клик по заголовку колонки сортирует список по этой колонке.
2. Цикл состояний при повторных кликах: **по возрастанию → по убыванию → без
   сортировки → по возрастанию** (соответствует циклу щелчка по заголовку в 1С 8.3).
3. Индикатор активной сортировки — стрелка в заголовке колонки:
   - `▲` — по возрастанию,
   - `▼` — по убыванию,
   - без стрелки — сортировки по этой колонке нет.
4. Сортировка применяется на сервере (`sort_by` + `sort_order`), не клиентски.
   Исключение — если список выгружен целиком и пагинация не используется
   (в текущей модели пагинация используется всегда).
5. При смене сортировки сбрасывается на страницу 1 и сохраняется активная
   страница не требуется — список перезагружается.
6. Пользовательская сортировка сохраняется (см. раздел 3.3.5: ключ `sort` в
   настройках списка) и восстанавливается при следующем открытии списка.
7. Сортировка по умолчанию при первом открытии (настроек нет) — текущая
   серверная (`date DESC`), значение по умолчанию задаётся в конфигурации списка.
8. Множественная сортировка (Shift+клик по нескольким колонкам) — вне рамок
   данной итерации (см. раздел 8, О1).

### 3.2. Фильтрация через поле фильтра

#### 3.2.1. Поле быстрого поиска (уже есть, стандартизируется)

- Текстовое поле над списком (слева в панели команд) — поиск по «основным»
  полям списка (номер, наименования, заказчик, объект и т.п.; состав полей —
  в конфигурации списка).
- Debounce 300 мс, сброс на страницу 1, `search` передаётся на сервер.

#### 3.2.2. Быстрый отбор по колонкам (новое)

1. Кнопка «Фильтр» в панели команд (справа) включает/выключает **строку
   быстрого отбора** — строку полей ввода под заголовками таблицы, по одному
   полю на колонку.
2. Тип поля отбора зависит от колонки (описывается в конфигурации списка):
   - текст: `input[type=text]`, сравнение «содержит» без учёта регистра;
   - число/сумма: `input[type=number]`, сравнение «равно»;
   - дата: `input[type=date]`, сравнение «равно»;
   - месяц/период: `input[type=month]` (как сейчас у табелей);
   - перечисление/статус (проведён/черновик, вид, направление): `select` со
     значениями из конфигурации, пустое значение = без отбора;
   - ссылочные поля (объект, смета, контрагент): `select` со списком
     справочника (выгрузка, как в TimesheetListView для объектов).
3. Отбор применяется серверно (параметр фильтра в запросе списка, раздел 4.2),
   при каждом изменении значения — debounce 300 мс, сброс на страницу 1.
4. Активные отборы показываются визуально (значение в поле строки отбора);
   кнопка «✕» в поле очищает отбор.
5. Быстрый отбор **не сохраняется** между сеансами (как в 1С быстрый отбор не
   сохраняется по умолчанию). Сохранение фильтров — О2 в разделе 8.

#### 3.2.3. Диалог «Отбор и сортировка»

Вне рамок данной итерации (полный диалог условий отбора — О3 в разделе 8).
Требования 3.2.1–3.2.2 полностью покрывают пункт «фильтр через поле фильтра».

### 3.3. Состав колонок с сохранением

1. Команда «Настройка списка» доступна в панели команд (справа) и внизу
   контекстного меню (как «Настройка списка» в 1С).
2. Диалог «Настройка списка» содержит:
   - список всех доступных полей списка с чекбоксами (видимость колонки);
   - кнопки «Вверх» / «Вниз» (порядок колонок);
   - кнопку «По умолчанию» (вернуть состав по умолчанию из конфигурации);
   - кнопки «ОК» / «Отмена».
3. При «ОК» настройка применяется немедленно к таблице (и к карточному виду на
   мобильных — скрытые колонки не показываются) и **сохраняется** (раздел 3.3.5).
   При «Отмена» — изменения отменяются.
4. Порядок колонок и видимость применяются к `DataTable` (пропс `columns`).
   Нельзя скрыть все колонки (минимум 1).
5. Сохранение настроек:
   - хранение: таблица `user_settings`, ключ `columns`, значение — JSON:
     ```json
     [ { "key": "number", "visible": true }, ... ]
     ```
     порядок элементов массива = порядок колонок. Метка колонки берётся из
     конфигурации списка, в настройке не хранится.
   - состав доступных полей (все возможные колонки) задаётся конфигурацией
     списка (раздел 5.2), настройка хранит только подмножество/порядок.
   - при появлении новых колонок в конфигурации они добавляются в конец
     видимого списка (по умолчанию видимы), сохранённые настройки не ломаются.
6. Ширина колонок: ресайз перетаскиванием границы заголовка — вне рамок
   данной итерации (О4 в разделе 8).
7. Сброс к умолчанию удаляет ключ `columns` для данного пользователя и формы.

### 3.4. Контекстное меню

1. ПКМ на строке списка открывает контекстное меню в точке курсора
   (существующий `ContextMenu.vue` дорабатывается: поддержка вложенных подменю
   и разделителей, раздел 5.4).
2. Состав меню (порядок сверху вниз):
   - «Открыть» — переход к форме документа (доступно при 1 строке);
   - «Изменить» — то же, что «Открыть» (дублирование по образцу 1С не требуется —
     оставить только «Открыть»);
   - разделитель;
   - «Копировать» — если у вида есть операция копирования (сметы, табели, ТМЦ);
   - «Провести» / «Отменить проведение» — по статусу строки; пункт активен в
     зависимости от прав пользователя (сейчас: `isAdmin` для документов,
     особые правила для табелей — бригадир только свои); для проведённых —
     «Отменить проведение», для черновиков — «Провести»; для строк, помеченных
     на удаление, — оба пункта неактивны;
   - разделитель;
   - «Пометить на удаление» — недоступно для проведённых;
   - «Снять пометку на удаление» — только для помеченных (сейчас уже есть);
   - разделитель;
   - «Ввод на основании» ▸ — только для документов с непустым реестром связей
     (раздел 3.6), только при выделении 1 строки;
   - разделитель;
   - «Настройка списка…» — внизу меню, как в 1С.
3. Пункты, недоступные в текущем состоянии строки/прав — `disabled`
   (полупрозрачные, не кликабельные) — сохранить текущее поведение.
4. Строки, помеченные на удаление (`marked_for_deletion`), отображаются
   зачёркнутыми и приглушёнными (как в 1С); для них недоступны «Провести»,
   «Отменить проведение», «Пометить на удаление».
5. Выделение: ПКМ по строке выделяет её (если строка не в выделении).

### 3.5. Панель команд объектов над списком

1. Единая панель команд над списком (замена текущих `SelectionActionBar` +
   кнопок тулбара). Состав команд — **декларативный конфиг** в настройке
   списка (раздел 5.2), а не отдельные кнопки в каждом ListView.
2. Левая часть панели — команды работы с объектами (видимость/доступность
   зависит от числа выделенных строк и прав):
   - «Создать …» — всегда доступна (сейчас в шапке через `useHeaderBar`);
   - «Открыть» — при 1 выделенной строке;
   - «Копировать» — при 1 строке, если операция есть;
   - «Провести» / «Отменить проведение» — при выделенных черновиках/
     проведённых соответственно (логика `canPostSelected`/`canUnpostSelected`),
     с учётом прав;
   - «Пометить на удаление» / «Удалить» — при выделенных строках
     (с подтверждением, как сейчас);
   - «Ввод на основании» ▸ — при 1 строке (документы с реестром связей);
   - «Обновить» ↻.
3. Правая часть панели (стабилизированные команды, как в 1С справа в панели
   команд списка):
   - «Фильтр» (toggle строки быстрого отбора, раздел 3.2.2);
   - «Настройка списка» (раздел 3.3);
   - «Обновить» ↻ (дублируется слева — не дублировать, разместить только справа).
4. Панель скрывает команды, недоступные в текущем состоянии (0 строк выделено
   и т.п.) — либо отображает их неактивными; единое правило: кнопки массовых
   операций над выделенным показываются только при наличии выделения (текущее
   поведение SelectionActionBar сохраняется).
5. Счётчик выделенных строк — в левой части панели (сейчас в SelectionActionBar).
6. Реализация: один общий компонент (раздел 5.2), каждый ListView передаёт
   только конфиг и обработчики.

### 3.6. Подменю «Ввод на основании» (документы)

#### 3.6.1. Общее поведение

1. Команда «Ввод на основании» доступна при выделении **ровно одной** строки
   (в панели команд и в контекстном меню).
2. Подменю содержит список документов, вводимых на основании текущего
   (реестр, раздел 3.6.2). Пункты — «Документ-результат: вид документа».
3. При выборе пункта открывается **форма нового документа** вида-результата
   с заполненным реквизитом «Документ-основание» и перенесёнными общими
   реквизитами (раздел 3.6.3).
4. Документ-основание отображается в форме нового документа (реквизит
   «Основание», нередактируемый) и сохраняется в БД (новое поле
   `based_on_type`/`based_on_id` в таблице документа-результата — единообразно
   для всех видов, раздел 4.4).
5. Проведение документа-основания не требуется; для черновиков-оснований
   команда доступна (в 1С доступна).

## 4. Требования к бэкенду

### 4.1. Сортировка

- Добавить параметры `sort_by` (вайтлист полей из конфигурации колонок
  списка) и `sort_order` (`asc`|`desc`) в list-эндпоинты, где их нет:
  `/api/cost/material-consumptions`, `machinery-usage-reports`,
  `subcontract-acceptances`, `overhead-expenses`, `cost-calculations`,
  `/api/goods/receipts`, `/api/goods/issues`,
  `/api/payments/schedules`, `/api/payments/transactions`.
- Валидация: неизвестный `sort_by` игнорируется (сортировка по умолчанию),
  как в `services.py:341`.
- Сервисы: параметры `sort_by`/`sort_order` в `cost_accounting_services.py`
  (все list_*), `goods_services.py`, `payment_services.py` по образцу
  `services.py:330-342`.

### 4.2. Быстрый отбор (фильтры колонок)

- Единое соглашение по параметрам: `f_<field>=<value>` для всех колонок
  списка, поддерживающих отбор (текст — LIKE «содержит», число/дата — равно,
  перечисление — равно).
- Уже существующие фильтры (`object_id`, `month_year`, `is_posted` у табелей)
  оставить как есть; для новых колонок использовать `f_`-префикс.
- Вайтлист отбираемых полей — из конфигурации колонок (поле `filterable`).
- Значение передаётся на сервер вместе с `page`/`page_size`/`search`/`sort_*`.

### 4.3. Настройки пользователя (состав колонок, сортировка)

Новые эндпоинты (роутер `system` или отдельный):

```
GET /api/system/user-settings/{form_name}           → { "columns": "...", "sort": "...", ... }
PUT /api/system/user-settings/{form_name}           ← JSON-объект записей
DELETE /api/system/user-settings/{form_name}/columns → сброс состава колонок к умолчанию
```

- Семантика: читает/пишет таблицу `user_settings` для текущего пользователя
  (`user_id` из токена), ключи = поля JSON-объекта, `setting_value` = строковое
  JSON-значение.
- Размер значения ограничить (например, 64 КБ) — защита от мусора.
- Схема не меняется (таблица уже есть, `database.py:786`).

### 4.4. Реквизит «Документ-основание»

- В таблицы документов-результатов (список из 3.6.2) добавить единообразные
  поля: `based_on_type TEXT` (doc_kind источника), `based_on_id INTEGER`,
  `based_on_number TEXT` (для отображения, денормализация как у остальных
  ссылок в этом проекте).
- Формы-результаты (create) принимают их в payload; список документов
  включает их в выборку (`based_on_number` для колонки «Основание», если
  колонка включена в конфигурацию).
- Миграции — по текущему механизму БД (CREATE TABLE IF NOT EXISTS + ALTER),
  с учётом sqlite/postgres бэкендов.

## 5. Требования к фронтенду

### 5.1. DataTable.vue (общий компонент таблицы)

- Пропс `sortable: boolean` и `sort: { key: string; order: 'asc'|'desc'|null }`;
  событие `@sort-change` при клике по заголовку (цикл ASC→DESC→null), стрелки
  в заголовке активной колонки.
- Пропс `filterable: boolean` — строка быстрого отбора под заголовками;
  тип поля по конфигурации колонки (`filter.type`); событие
  `@filter-change(field, value)`.
- Пропс `columns` расширяется: `{ key, label, visible, sortable, filterable,
  filter?: { type: 'text'|'number'|'date'|'month'|'select', options?: [...] } }`.
  Видимые колонки = `columns.filter(c => c.visible)` (порядок — порядок массива).
- Зачёркивание строк `marked_for_deletion` (класс `row-marked`).
- Сохранение поведения выделения, мобильных карточек (скрытые колонки не
  выводятся и в карточках).

### 5.2. Общий composable и конфиг списка

- `useDocumentList(config)` — единый механизм списка (раздел обсуждался ранее):
  состояние (rows/loading/error/search/page/pagination/selectedIds/sort/filters),
  `loadItems()` (сбор query: page, page_size, search, sort_by, sort_order,
  f_* фильтры), команды (post/unpost/delete/restore/copy), вычисляемые
  доступности (canPostSelected и т.п.), watchers (debounce 300 мс).
- Конфигурация списка (статический модуль на каждый doc_kind):
  ```ts
  {
    formName: 'estimates',
    title: 'Сметы',
    createLabel: 'Создать смету',
    createRoute: '/documents/estimates/new',
    defaultSort: { key: 'date', order: 'desc' },
    api: { list, get?, post?, unpost?, remove?, restore?, copy? },
    columns: [ { key, label, sortable?, filterable?, filter? }, ... ],  // полный состав
    baseOn: [ { kind: 'daily-reports', label: 'Дневной отчёт', ... }, ... ], // раздел 3.6
    routeBase: '/documents/estimates',
  }
  ```
- `useListSettings(formName)` — загрузка/сохранение настроек (GET/PUT
  `/api/system/user-settings/...`), применяет `columns` (видимость/порядок)
  и `sort` при инициализации списка.

### 5.3. Компоненты (новые)

- `ListCommandBar.vue` — панель команд объектов (раздел 3.5), принимает
  конфиг команд + состояние из `useDocumentList` + слот для дополнительных
  команд вида (например, «Печать», «Обмен данными»).
- `ListSettingsDialog.vue` — диалог «Настройка списка» (раздел 3.3): чекбоксы
  видимости, «Вверх/Вниз», «По умолчанию», «ОК/Отмена».
- `ListFilterRow` — интегрируется в DataTable (раздел 5.1), отдельный

## 7. Критерии приёмки (общие, применяются к каждому списку)

1. Клик по заголовку сортирует список на сервере, стрелка показывает
   направление; третий клик снимает сортировку.
2. Сортировка и состав колонок сохраняются и восстанавливаются после
   повторного входа пользователя (другой пользователь видит свои настройки).
3. Включение строки быстрого отбора и фильтрация по каждой колонке работают
   с debounce и серверной пагинацией.
4. ПКМ на строке открывает контекстное меню: состав и активность пунктов
   соответствуют разделу 3.4 (статус строки, права).
5. Панель команд объектов показывает корректные команды в зависимости от
   выделения и прав.
6. «Ввод на основании» доступен для документов из реестра 3.6.2 при 1
   выделенной строке; открывается новая форма с реквизитом «Основание».
7. Для каждого вида документа команды delete/restore имеют симметричные backend
   endpoints и проверяются с учётом статуса и роли; недоступная операция не
   показывается как рабочая команда.
8. Регресс: существующие функции списков (поиск, пагинация, выделение,
   печать, обмен данными) не сломаны.
