# Спецификация формы «Регистр работ»

Версия: 0.1 (черновик)
Обновлено: 2026-08-01
Статус: требования добавляются итеративно.

---

## 1. Цель и область применения

Регистр работ — аналитическая форма для просмотра движений по выполненным работам
с возможностью группировки, фильтрации и детализации. Регистр отражает приход
(сметные объёмы) и расход (фактическое выполнение) по работам в разрезе объектов,
смет, заказчиков и договоров.

### 1.1. Назначение

- Контроль выполнения работ по объектам и сметам
- Анализ баланса между сметными и фактическими объёмами
- Формирование данных для расчёта себестоимости и платежей
- Основание для создания документов «на основании» (платежи, расход материалов)

### 1.2. Источники данных

| Источник | Тип recorder_type | Описание |
|---|---|---|
| Смета (estimate) | `estimate` | Сметные объёмы работ (приход) |
| Дневной отчёт (daily_report) | `daily_report` | Фактическое выполнение (расход) |

### 1.3. Место в системе

```
Справочники: Объекты, Сметы, Работы, Заказчики, Договоры
        │
        ▼
Документы: Сметы ──────┐
           Дневные отчёты ─┘
        │
        ▼
Регистр работ ◄──── (движения work_execution_register)
        │
        ▼
Отчёты: Себестоимость, Платежи, ТМЦ
```

| Фильтры: период, объект, смета, работа, заказчик, договор | ✅ | Выпадающие списки с серверной загрузкой |

- Сортировка кликом по заголовку колонки

- Сохранение настроек пользователя (состав колонок, сортировка)
- Контекстное меню (ПКМ)
- Панель команд объектов
- Экспорт данных (Excel/CSV)
- Печатная форма
- Полноценная серверная пагинация

## 3. Целевое поведение (TO-BE)

### 3.1. Сортировка по заголовку колонки

1. Клик по заголовку сортирует список по этой колонке.
2. Цикл состояний: **по возрастанию → по убыванию → без сортировки → по возрастанию**.
3. Индикатор: `▲` — по возрастанию, `▼` — по убыванию, без стрелки — без сортировки.
4. Сортировка серверная (`sort_by` + `sort_order`).
5. При смене сортировки — сброс на страницу 1.
6. Пользовательская сортировка сохраняется (ключ `sort` в настройках).
7. Сортировка по умолчанию: `period DESC, id DESC`.

### 3.2. Фильтрация

#### 3.2.1. Поле быстрого поиска (уже есть)

- Текстовое поле над списком — поиск по наименованию работы, коду, номеру сметы/документа.
- Debounce 300 мс, сброс на страницу 1.

#### 3.2.2. Быстрый отбор по колонкам (новое)

1. Кнопка «Фильтр» включает/выключает строку полей ввода под заголовками.
2. Тип поля по колонке:

| Колонка | Тип поля | Сравнение |
|---|---|---|
| Период | `input[type=date]` | диапазон (с/по) |
| Регистратор | `input[type=text]` | содержит |
| Заказчик | `select` (справочник) | равно |
| Договор | `select` (справочник) | равно |
| Объект | `select` (справочник) | равно |
| Смета | `select` (справочник) | равно |
| Работа | `select` (справочник) | равно |
| Приход кол-во | `input[type=number]` | диапазон |
| Расход кол-во | `input[type=number]` | диапазон |
| Приход сумма | `input[type=number]` | диапазон |
| Расход сумма | `input[type=number]` | диапазон |
| Баланс | `input[type=number]` | диапазон |

3. Отбор серверный (параметры `f_<field>`), debounce 300 мс, сброс на страницу 1.
4. Кнопка «✕» в поле очищает отбор.
5. Быстрый отбор **не сохраняется** между сеансами.

### 3.3. Состав колонок с сохранением

1. Команда «Настройка списка» в панели команд и в контекстном меню.
2. Диалог «Настройка списка»:
   - Список всех колонок с чекбоксами видимости;
   - Кнопки «Вверх» / «Вниз» (порядок);
   - Кнопка «По умолчанию»;
   - Кнопки «ОК» / «Отмена».
3. Сохранение в `user_settings` (ключ `columns`, значение — JSON-массив).
4. Нельзя скрыть все колонки (минимум 1).

### 3.4. Контекстное меню

1. ПКМ на строке открывает меню в точке курсора.
2. Состав меню:
   - «Открыть детализацию» — модальное окно движений;
   - разделитель;
   - «Перейти к смете» — если есть estimate_id;
   - «Перейти к дневному отчёту» — если recorder_type = daily_report;
   - разделитель;
   - «Настройка списка…».

### 3.5. Панель команд объектов

1. Единая панель над списком.
2. Левая часть:
   - «Обновить» ↻;
   - «Экспорт» ▸ (Excel, CSV).
3. Правая часть:
   - «Фильтр» (toggle строки быстрого отбора);
   - «Настройка списка».

### 3.6. Детализация (двойной клик)

1. Двойной клик по строке открывает модальное окно «Детализация движений».
2. В окне — таблица движений с фильтрами по периоду и объекту.
3. Двойной клик по движению — переход к исходному документу (смета/дневной отчёт).
4. Кнопка «Закрыть» внизу окна.

### 3.7. Экспорт данных

1. Кнопка «Экспорт» в панели команд.
2. Форматы: Excel (.xlsx), CSV (.csv).
3. Экспорт учитывает текущие фильтры и сортировку.
4. Состав колонок — видимые колонки (с учётом настроек).
5. Итоги экспортируются в 마지막ней строке.

### 3.8. Печатная форма

1. Кнопка «Печать» в панели команд.
2. Формат: HTML (для печати из браузера) или PDF.
3. Макет: шапка (период, объект, смета), таблица движений, итоги.

## 4. Требования к бэкенду

### 4.1. Сортировка

Добавить параметры в `GET /api/registers/work-execution`:

```
sort_by: str  — вайтлист полей из колонок
sort_order: str — "asc" | "desc"
```

Вайтлист: `period`, `recorder_number`, `customer_name`, `contract_number`,
`object_name`, `estimate_number`, `work_name`, `quantity_income`,
`quantity_expense`, `sum_income`, `sum_expense`, `balance_sum`.

### 4.2. Быстрый отбор (фильтры колонок)

Параметры запроса:

| Параметр | Тип | Описание |
|---|---|---|
| `f_period_from` | str | Период с (дата) |
| `f_period_to` | str | Период по (дата) |
| `f_recorder` | str | Регистратор (contains) |
| `f_customer_id` | int | Заказчик (равно) |
| `f_contract_id` | int | Договор (равно) |
| `f_object_id` | int | Объект (равно) |
| `f_estimate_id` | int | Смета (равно) |
| `f_work_id` | int | Работа (равно) |
| `f_quantity_income_from` | float | Приход кол-во от |
| `f_quantity_income_to` | float | Приход кол-во до |
| `f_quantity_expense_from` | float | Расход кол-во от |
| `f_quantity_expense_to` | float | Расход кол-во до |
| `f_sum_income_from` | float | Приход сумма от |
| `f_sum_income_to` | float | Приход сумма до |
| `f_sum_expense_from` | float | Расход сумма от |
| `f_sum_expense_to` | float | Расход сумма до |

### 4.3. Пагинация

Серверная пагинация (уже реализована в `query_work_execution`).

### 4.4. Экспорт

```
GET /api/registers/work-execution/export
```

Параметры: те же, что у основного запроса + `format: xlsx | csv`.

Ответ: файл (binary).

### 4.5. Настройки пользователя

Использовать общий механизм `user_settings`:

```
GET  /api/system/user-settings/works-register
PUT  /api/system/user-settings/works-register
```

Ключи: `columns` (состав колонок), `sort` (сортировка).

## 7. Критерии приёмки

1. Клик по заголовку сортирует список на сервере; третий клик снимает сортировку.
2. Сортировка и состав колонок сохраняются и восстанавливаются.
3. Строка быстрого отбора работает по всем колонкам с debounce.
4. ПКМ на строке открывает контекстное меню с корректными пунктами.
5. Панель команд показывает корректные команды.
6. Двойной клик по строке открывает детализацию; двойной клик по движению — документ.
7. Экспорт в Excel/CSV учитывает фильтры и настройки колонок.
8. Печатная форма корректно отображает данные.
8. Регресс: существующие функции (поиск, фильтры, группировка, метрики) не сломаны.
