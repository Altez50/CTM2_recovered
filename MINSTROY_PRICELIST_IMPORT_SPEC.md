# Спецификация: загрузка расценок Минстроя (ФЕР/ГЭСН) в каталог работ

Обновлено: 2026-08-24

---

## 1. Цель

Загружать официальные нормативные базы Минстроя России — **ФЕР**
(федеральные единичные расценки) и **ГЭСН** (государственные элементные
сметные нормы) — в каталог работ CTM: работы со стоимостью и трудоёмкостью
плюс ресурсный состав (спецификации: труд, машины, материалы). Это даёт
подрядчику готовую НСИ для смет и расчёта себестоимости без ручного набора
и без покупки сметной программы только ради справочника.

## 3. Требования (TO-BE)

### 3.1. Поддерживаемые форматы

| Источник | Формат | Что берём |
|---|---|---|
| ФЕР (сборники, XML Минстроя) | XML | шифр, наименование, измеритель, состав работ, раскладка стоимости в базисных ценах 2001 г., ресурсы с нормами расхода |
| ГЭСН (сборники, XML Минстроя) | XML | то же без готовой цены (нормы ресурсов) |
| Универсальный шаблон | XLSX/CSV | колонки фиксированы шаблоном (для ТЕР, ФССЦ и выгрузок ГрандСметы) — переиспользуем профили импорта |

Ограничение фазы 1: официальные XML-выгрузки Минстроя (структура
«сборник → разделы → таблицы → расценки → ресурсы»); всё остальное —
через шаблон XLSX.

### 3.2. Маппинг ФЕР/ГЭСН → CTM

| Элемент расценки | CTM |
|---|---|
| Шифр расценки (напр. `06-01-001-01`) | `works.code` (уникален в группе) |
| Наименование работы | `works.name` |
| Измеритель расценки | `works.unit` (нормализация через `_normalize_unit_name`, правила ниже) |
| Прямые затраты (всего, базис 2001) | `works.price` |
| Затраты труда рабочих, чел.-ч на измеритель | `works.labor_rate` |
| Затраты труда машинистов | строка спецификации `component_type = труд` |
| Эксплуатация машин (состав, маш.-ч, цена маш.-ч) | спецификации `component_type = машина` (+ строка «в т.ч. зарплата машинистов» — `прочее` или объединение, по настройке) |
| Материалы (код ФССЦ, наименование, расход, цена) | спецификации `component_type = материал`, `material_id` → автосоздание карточки материала с кодом ФССЦ |
| Состав работ (технология) | `works.description` (новое поле, phase 2) или `specification_review_note` |

Правила нормализации измерителя (типовые):
`100 м2` → ед. `м²`, норма расхода ресурсов делится/умножается на 100
(расценка остаётся «на 100 м²», в CTM норма хранится **на единицу работы**,
поэтому `consumption_rate = норма_ГЭСН / 100` при измерителе `100 …`);
`1000 шт.` → `шт.`, аналогично. Нетиповой измеритель — как есть + warning.

### 3.3. Индекс пересчёта цен

Расценки ФЕР даны в базисе 2001 г. На шаге применения пользователь задаёт
**единый индекс** (множитель) к `works.price` и к `unit_price` строк
спецификаций (обычно СМР-индекс региона). Индекс применяется один раз
при загрузке; в `works.code` сохраняется исходный шифр, факт загрузки
с индексом фиксируется в отчёте импорта. По умолчанию индекс = 1.

### 3.4. Структура групп

Строится иерархия групп работ: `ФЕР {год}` → `Сборник {шифр} {наименование}`
→ `Раздел {номер}` → работы. Корневая группа именуется
`ФЕР 2022 / ФЕРм 2022 / ГЭСН 2022` по типу файла. Повторная загрузка того
же сборника находит существующую группу по имени корня.

### 3.5. Конфликты по коду работы

Если работа с тем же `code` уже существует (в целевой группе):

| Режим | Поведение |
|---|---|
| `skip` *(по умолчанию)* | пропустить, в отчёт |
| `update` | обновить name/unit/price/labor_rate и **заменить** спецификации |
| `create` | создать дубль с суффиксом кода `-Н` |

Режим выбирается в мастере; конфликт по коду, но с другим наименованием —
warning «проверьте, это не тот же вид работ».

### 3.6. API

```
POST /api/works/normative-base/preview
  multipart: file, mode=(works|works_and_specs)
  Ответ: {
    "source": "fer-2022", "collection": "ФЕР 06 Бетонные конструкции",
    "works_total": 214, "groups": 9, "specs_total": 1523,
    "units_to_create": 14, "materials_to_create": 487,
    "conflicts": [ {"code": "06-01-001-01", "existing_id": 55, "name_differs": false} ],
    "warnings": [ ... ],
    "sample": [ первые 20 расценок ]
  }

POST /api/works/normative-base/apply
  multipart: file, mode, conflict_resolution=(skip|update|create),
  index (float, default 1.0), root_group_name (default из файла)
  Ответ: {
    "works_created": 208, "works_updated": 0, "works_skipped": 6,
    "specs_created": 1490, "materials_created": 480, "units_created": 14,
    "warnings": [ ... ]
  }

GET /api/works/normative-base/template
  XLSX-шаблон универсального формата
```

Права: `admin` (массовое изменение НСИ). Применение выполняется батчами
в одной транзакции на сборник; объём ФЕР — десятки тысяч расценок,
поэтому разбор файла и вставка идут потоково, без полной загрузки в память.

### 3.7. UI

Мастер в `WorkCatalogView.vue` («Ещё → Загрузить расценки Минстроя»):

1. Выбор файла (XML/XLSX), автораспознавание типа (ФЕР/ГЭСН/шаблон).
2. Сводка предпросмотра: сборник, кол-во работ/ресурсов, новые материалы,
   единицы, конфликты (с выбором режима), поле «Индекс к ценам».
3. Применение с прогрессом (батчи) → итоговый отчёт (кол-во созданного,
   предупреждения) с экспортом отчёта в XLSX.

Ничего не меняется в `WorkForm` и журналах: загруженные работы — обычные
элементы каталога (можно править, копировать спецификации и т. д.).

### 3.8. Синхронизация

Все создаваемые записи получают uuid и `updated_at` — peer-синхронизация
штатная. Большой объём одного применения может превысить пакет обмена —
обмен заберёт изменения несколькими пачками, доработок не требуется
(подтвердить на объёме одного сборника ФЕР в тесте приёмки).

---

## 4. Не входит в объём (Out of scope)

- Автоматическое применение территориальных/отраслевых индексов по региону
  (только ручной единый индекс).
- Хранение базисной и текущей цены одновременно (индексная модель —
  отдельная фича).
- Импорт ФССЦп/ЭССЦ как самостоятельных справочников цен на ресурсы
  (материалы создаются из состава расценок).
- Обновление загруженных работ при выходе новой редакции сборника
  (повторная загрузка в режиме `update` закрывает сценарий).

---

## 5. Критерии приёмки

1. XML-сборник ФЕР загружается: создаются группы (сборник/раздел), работы
   с ценой (× индекс) и трудоёмкостью, спецификации труд/машины/материалы
   с нормами на единицу работы.
2. Измерители `100 м2`, `1000 шт.` нормализуются, нормы делятся на 100/1000;
   нетиповые — warning, загрузка не блокируется.
3. Материалы ФССЦ создаются с кодом и не дублируются при повторной загрузке
   (резолв код → наименование).
4. Конфликт кода работает во всех трёх режимах (`skip/update/create`).
5. Повторная загрузка того же сборника в `skip` — идемпотентна (0 созданного).
6. Загрузка сборника (~5 тыс. расценок) укладывается в таймаут запроса;
   память не растёт линейно (потоковый разбор).
7. Все созданные записи синхронизируются на второй узел и видимы там в
   каталоге работ без ручных действий.
8. Роль `foreman` не имеет доступа к эндпоинтам загрузки.
