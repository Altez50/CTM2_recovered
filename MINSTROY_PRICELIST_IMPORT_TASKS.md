# Задачи: загрузка расценок Минстроя (ФЕР/ГЭСН)

Спецификация: [MINSTROY_PRICELIST_IMPORT_SPEC.md](MINSTROY_PRICELIST_IMPORT_SPEC.md)
Статус: не начато; старт после закрытия P0/P1 из `DEVELOPMENT_PLAN.md`.
Оценка — чистая разработка, 1 fullstack-разработчик, без ревью/UAT.

---

## Фаза 0. Исследование формата

- [ ] **P0.1. Получить эталонные XML** — по 2–3 сборника ФЕР, ФЕРм, ГЭСН
      (разные редакции: 2014/2022) + примеры выгрузок ГрандСметы. — **3 ч**
- [ ] **P0.2. Прототип разбора и карта маппинга** — разобрать структуру
      (сборник → разделы → таблицы → расценки → ресурсы), зафиксировать
      различия редакций, таблица соответствий полей CTM. — **5 ч**

## Фаза 1. Backend

- [ ] **B1. Потоковый парсер XML** — `xml.etree.iterparse`: сборник
      (мета, шифр, наименование), разделы, расценки (шифр, наименование,
      измеритель, ПЗ всего, трудозатраты чел.-ч), ресурсы (тип, код, имя,
      расход, цена). Генератор записей, без полной загрузки в память. — **12 ч**
- [ ] **B2. Нормализация измерителей** — таблица правил (`100 м2` → `м²`
      /делить на 100 и т.п.), нетиповые → warning. — **3 ч**
- [ ] **B3. Разрешение/создание справочников** — материалы по коду ФССЦ →
      наименованию (переиспользовать `_find_material_by_code_or_name`),
      единицы через `_resolve_unit_id`, детект дублей имён. — **5 ч**
- [ ] **B4. Иерархия групп и конфликты** — создание
      `ФЕР {год} → Сборник → Раздел`; поиск корня по имени; режимы
      `skip/update/create` по `works.code` (update = замена спецификаций). — **6 ч**
- [ ] **B5. Применение: работы + спецификации** — батчевые вставки,
      после design gate выбрать atomic collection либо resumable job;
      checkpoint/resume/rollback для второго варианта, индекс к ценам,
      `component_type` труд/машина/материал/прочее. — **8 ч**
- [ ] **B6. Эндпоинт preview** — агрегация (счётчики, конфликты, warnings,
      sample 20). — **4 ч**
- [ ] **B7. Эндпоинт apply + отчёт** — file hash + idempotency key, job/progress
      по батчам при resumable-контракте, итоговый отчёт
      (created/updated/skipped/checkpoint), экспорт отчёта XLSX. — **8 ч**
- [ ] **B8. Универсальный XLSX-шаблон** — генерация шаблона
      (`GET .../template`) и импорт по нему (переиспользовать профили
      импорта спецификаций). — **6 ч**
- [ ] **B9. Права** — эндпоинты только admin (require_roles). — **1 ч**
- [ ] **B10. Тесты** — фикстура мини-сборника (2 раздела, ~30 расценок,
      все типы ресурсов + измерители «100 …», «1000 шт.»); идемпотентность
      apply; три режима конфликтов; нормализация норм; права; сбой/отмена в
      середине apply и проверка rollback/resume. — **10 ч**

## Фаза 2. Frontend

- [ ] **F1. Мастер загрузки (3 шага)** в WorkCatalogView («Ещё → Загрузить
      расценки Минстроя»): файл+автоопределение типа → сводка/конфликты/
      индекс → прогресс+отчёт. — **10 ч**
- [ ] **F2. Отчёт применения с экспортом XLSX** и списком warnings. — **3 ч**

## Фаза 3. QA / приёмка

- [ ] **Q1. Нагрузочный прогон** — полный сборник ФЕР (~5 тыс. расценок):
      время preview/apply, память, отсутствие таймаутов. — **4 ч**
- [ ] **Q2. Каталог после загрузки** — производительность поиска/пагинации
      WorkCatalogView на ~50 тыс. работ. — **3 ч**
- [ ] **Q3. Sync** — доставка большого объёма на второй узел несколькими
      пачками, целостность каталога там. — **3 ч**
- [ ] **Q4. Прогон критериев приёмки спеки** (8 пунктов) + краткая
      инструкция пользователю. — **3 ч**
